## Architecture of TGEControllerV2

The V1 `distributeWelcomeBonus(recipients[], amounts[])` took an undifferentiated array with no on-chain checks. V2 splits it:

```solidity
distributeWelcomeBonus(
    address userRecipient,         // capped + deduped lifetime (1000 DIASPORA)
    uint256 userAmount,
    address[] treasuryRecipients,  // founders, liquidity, burn, community slots
    uint256[] treasuryAmounts,     // uncapped (each signup legitimately adds)
    bytes32 merkleRoot             // commitment to the full distribution
)
```

Why not auto-detect treasuries via the WalletFactory: both user wallets AND treasury wallets are created through the same factory (just with different salts — `keccak256(phoneNumber)` for users, `keccak256("system:founders_treasury")` etc. for treasuries). The factory can't distinguish them. The explicit split signature is cleaner than an admin-managed exempt list.

Also fixes V1's burn-accounting bug (amounts double-counted in `totalDistributed` and `totalBurned`, producing the 1000 DIASPORA drift visible on-chain). V2-era distributions have exact zero drift; the historical V1 drift is preserved as a one-time artifact.
